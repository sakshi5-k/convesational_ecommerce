Conversational Search for an eCommerce Application

A mobile eCommerce app where the primary way to shop is by typing what you want in plain English — e.g. "Show me running shoes under ₹5,000 suitable for beginners" — and getting back a ranked set of matching products, each with a short explanation of why it was picked.

Built with React Native (Expo) on the frontend and FastAPI + OpenAI on the backend.

The app parses this into structured intent — category: Footwear, subcategory: Running Shoes, max\_price: 5000, audience: beginner — scores the catalog against it, and returns the top matches with a "Why this matches" reason attached to each product card.

Features 🗣️ Conversational search — natural-language query box as the home-screen hero 🧠 AI intent parsing — LLM extracts category, subcategory, price range, brand, audience, and desired features from free text 💡 "Why this matches" — a per-product explanation sheet, generated by the LLM from the actual matched attributes 🧮 Deterministic ranking — a transparent scoring function ranks candidates, so results stay fast and reproducible even if an LLM call fails 🗂️ Browse view — category chips on the home screen when there's no active search ❤️ Wishlist — toggle from cards or detail screen, dedicated tab with badge 🛒 Cart — quantity controls, remove, live subtotal, badge on tab 📦 Product detail — hero image, features, description, tags, sticky Add to Cart 💳 Mocked checkout — address + COD / UPI / Card selector → order confirmation 🔄 Graceful degradation — with no OpenAI key set, falls back to plain keyword search instead of breaking Architecture

Frontend: Expo (SDK 54) + expo-router file-based navigation, talking to the backend over a REST API defined by EXPO\_PUBLIC\_BACKEND\_URL. Backend: a single FastAPI app (/api prefix) handling search, catalog browsing, cart, wishlist, and checkout. AI: OpenAI's Chat Completions API, called twice per search — once to turn the query into structured intent, once to write the summary + per-product reasons. Ranking: deterministic and LLM-independent (backend/server.py::\_score\_product) — weights price fit, category/subcategory match, brand, audience, and keyword/feature overlap. The LLM explains the match; it doesn't decide it. Data store: in-memory (backend/memory\_db.py), seeded from a 40-product catalog (backend/catalog.py) spanning Footwear, Electronics, Apparel, Home & Kitchen, Sports, Beauty, Books, Toys, Health, and Accessories — all priced in INR. No database server required; data resets on backend restart. Setup instructions Prerequisites Python 3.10+ Node.js 18+ and Yarn (npm install -g yarn) An OpenAI API key (optional — see Known limitations) Expo Go app on your phone (optional — for testing on a physical device)

Backend bash cd backend python3 -m venv venv source venv/bin/activate # Windows: venv\Scripts\activate pip install -r requirements.txt
Add your OpenAI key to backend/.env:

OPENAI\_API\_KEY=sk-... OPENAI\_MODEL=gpt-4o-mini

Run the server:

bash python server.py # or: uvicorn server\:app --reload

Health check: [http://localhost:8000/api/](http://localhost:8000/api/)

Frontend bash cd frontend yarn install yarn start
Press w for web, or scan the QR code with Expo Go on your phone.

If testing on a physical phone, localhost in frontend/.env won't reach your laptop — set EXPO\_PUBLIC\_BACKEND\_URL to your machine's LAN IP instead (e.g. [http://192.168.1.5:8000](http://192.168.1.5:8000)), found via ipconfig / ifconfig, with the phone on the same Wi-Fi network.

Running tests bash cd backend pytest Notes The product catalog (40 items) reseeds on every backend restart; there's no database server to install. Carts/wishlists/orders created during a session are lost on backend restart. frontend/scripts/cmd-guard.js is a leftover guardrail from the platform this project was originally scaffolded on (Emergent) — it's inert for a normal yarn install and can be removed from frontend/package.json's "preinstall" script if it ever complains. Navigation: bottom tabs — Search (home), Wishlist, Cart — each with a live badge. Session: a client-generated ID persisted in AsyncStorage, used to scope cart, wishlist, and search history without requiring login. Known limitations No OpenAI key → no NL understanding. If OPENAI\_API\_KEY is left blank, the backend skips both LLM calls and falls back to plain keyword/category matching. The app still runs and returns results, but loses the intent parsing and the generated "why this matches" reasons — the core conversational feature. No persistence. Everything (catalog, carts, wishlists, orders) lives in-process and resets when the backend restarts — there's no database. Checkout is mocked.
